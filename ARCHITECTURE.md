# Architecture

`@contentful/experience-delivery` is a TypeScript client for Contentful's
Experience Delivery and Preview API. This document describes how the package is
put together, where the boundaries are, and which parts are generated.

For contributor workflow see [CONTRIBUTING.md](./CONTRIBUTING.md); for
consuming a local build see [BUILDING.md](./BUILDING.md); for agent-specific
constraints see [AGENTS.md](./AGENTS.md).

## Generation pipeline

The package is generated by [Fern](https://buildwithfern.com) from an API
definition maintained in a separate repository. `.fern/metadata.json` records
the exact provenance of the checked-in output:

| Field | Value |
| --- | --- |
| `cliVersion` | `5.45.3` |
| `generatorName` | `fernapi/fern-typescript-node-sdk` |
| `generatorVersion` | `3.70.6` |
| `namespaceExport` | `ContentfulViewDelivery` |
| `originGitCommit` | `4e878a3cc88c52d6d6165f6e4ad46bb26dafec60` (commit in the API-definition repo) |
| `sdkVersion` | `0.0.0-fern-placeholder.6` |

Three generator settings shape the runtime behaviour more than anything else in
this repo:

- `noSerdeLayer: false` — a full serialization layer is generated under
  `src/serialization/`, so responses are parsed through schemas rather than cast.
- `skipResponseValidation: true` and `allowExtraFields: true` — those schemas
  parse permissively. A response with unexpected fields, or one that does not
  match the schema, does not throw; the API can add fields without breaking
  installed clients.
- `generateWireTests: false` / `writeUnitTests: false` — no endpoint tests are
  generated. See [Tests](#tests).

Regenerations arrive as `SDK regeneration` pull requests authored by
`fern-api[bot]`. Hand-maintained files are protected by `.fernignore`, with
`.fern/replay.lock` as a secondary mechanism that reapplies hand-made commits
on top of new output — see
[docs/ADRs/2026-08-25-preserve-hand-maintained-files-across-fern-regeneration.md](./docs/ADRs/2026-08-25-preserve-hand-maintained-files-across-fern-regeneration.md).
`.fern/verify.sh` is the generator's post-generation gate: `pnpm install`,
`pnpm build`, `pnpm test`.

## Layers

```
src/index.ts                  public entry point (re-exports)
  └─ src/Client.ts            ContentfulViewDeliveryClient — lazy resource getters + .fetch()
       └─ src/BaseClient.ts   option normalization, header injection, auth provider selection
            ├─ src/auth/      BearerAuthProvider
            ├─ src/core/      transport and runtime primitives (not API-specific)
            └─ src/api/       one client + types per API resource
                 └─ src/serialization/  request/response schemas per resource
```

### `src/index.ts` — the public surface

```typescript
export * as ContentfulViewDelivery from "./api/index.js";   // all request/response types
export type { BaseClientOptions, BaseRequestOptions } from "./BaseClient.js";
export { ContentfulViewDeliveryClient } from "./Client.js";
export { ContentfulViewDeliveryEnvironment } from "./environments.js";
export { ContentfulViewDeliveryError, ContentfulViewDeliveryTimeoutError } from "./errors/index.js";
export * from "./exports.js";                                // core primitives
export * as serialization from "./serialization/index.js";
```

### `src/Client.ts` — the root client

`ContentfulViewDeliveryClient` holds normalized options and exposes one lazily
constructed sub-client per resource (`this._experience ??= new ExperienceClient(...)`),
so importing the root client does not instantiate the whole tree.

It also exposes `client.fetch(input, init, requestOptions)`, a passthrough
escape hatch (`core.makePassthroughRequest`) that reuses the SDK's auth, retry,
timeout and logging configuration to call endpoints the SDK does not yet model.

### `src/BaseClient.ts` — options and auth

`normalizeClientOptions` merges the caller's headers over a fixed set the SDK
always sends: `X-Fern-Language`, `X-Fern-SDK-Name`, `X-Fern-SDK-Version`,
`User-Agent`, `X-Fern-Runtime`, `X-Fern-Runtime-Version`, and
`x-contentful-enable-alpha-feature` (defaulting to `"new-exo-entity-types"`).
That last header is Contentful-specific and is overridable per client and per
request via `xContentfulEnableAlphaFeature`.

`normalizeClientOptionsWithAuth` resolves the `auth` option in priority order:
`false` → `NoOpAuthProvider`; a function → used as `getAuthRequest`; an
`AuthProvider` → used directly; otherwise `BearerAuthProvider` built from the
token options.

### `src/core/` — transport and runtime

Not API-specific; this is the generator's runtime library.

| Directory | Responsibility |
| --- | --- |
| `core/fetcher/` | `Fetcher`, `makeRequest`, `requestWithRetries`, `HttpResponsePromise`, `RawResponse`, `createRequestUrl`, abort `signals`, `Supplier` |
| `core/schemas/` | The schema builder library (`object`, `union`, `undiscriminated-union`, `record`, `list`, `set`, `enum`, `literals`, `date`, `bigint`, `lazy`, primitives) backing `src/serialization/` |
| `core/url/` | `join`, `qs`, `QueryStringBuilder` |
| `core/logging/` | `LogLevel`, `ConsoleLogger`, the `ILogger` interface |
| `core/runtime/` | Runtime detection, surfaced as the `X-Fern-Runtime*` headers |
| `core/auth/` | `AuthProvider` contract, `NoOpAuthProvider` |
| `core/headers.ts`, `core/base64.ts`, `core/json.ts` | Header merging (`mergeHeaders`, `mergeOnlyDefinedHeaders`) and encoding helpers |

`HttpResponsePromise` is why every endpoint can be awaited directly for the
parsed body *or* awaited via `.withRawResponse()` for `{ data, rawResponse }`.

### `src/api/` — resources

Six top-level resources, each with `client/Client.ts`, `client/requests/`, and
(where the resource owns types) `types/`:

| Resource | Client property |
| --- | --- |
| `experience` | `client.experience` |
| `template` | `client.template` |
| `component` | `client.component` |
| `fragment` | `client.fragment` |
| `experienceFragment` | `client.experienceFragment` |
| `release` | `client.release`, with nested `release/experience` and `release/fragment` |

`src/api/types/` holds the 230 shared model types (`ComponentTreeNode`,
`DesignToken`, `DeliveryExperienceSys`, the per-status error bodies, and so on).

Endpoint methods return `core.HttpResponsePromise<T>` and delegate to a private
`__method` that assembles query params, resolves auth via
`this._options.authProvider.getAuthRequest()`, merges headers, and calls
`core.fetcher`.

### Errors — two distinct sets

- `src/errors/` — transport-level: `ContentfulViewDeliveryError` (the base class
  carrying `statusCode`, `body`, `rawResponse`), `ContentfulViewDeliveryTimeoutError`,
  and `handleNonStatusCodeError`.
- `src/api/errors/` — one subclass per modelled HTTP status:
  `BadRequestError`, `UnauthorizedError`, `ForbiddenError`, `NotFoundError`,
  `ConflictError`, `UnprocessableEntityError`, `InternalServerError`.

Callers catch `ContentfulViewDeliveryError` to catch everything.

## Environments

`src/environments.ts` declares exactly one environment:

```typescript
export const ContentfulViewDeliveryEnvironment = {
    Default: "https://xdn.contentful.com",
} as const;
```

Preview is *not* a separate environment constant — it is reached by constructing
a second client with `baseUrl: "https://preview.xdn.contentful.com"` and a CPA
token, as documented in the README. Authentication is a bearer token by default,
with an `access_token` query parameter alternative for contexts that cannot set
the `Authorization` header.

## Build topology

There is no bundler in the build path. `pnpm build` runs two `tsc` invocations
over the same `src/`:

- `pnpm build:cjs` → `tsc --project ./tsconfig.cjs.json` → `dist/cjs/` (`module: CommonJS`)
- `pnpm build:esm` → `tsc --project ./tsconfig.esm.json` → `dist/esm/`
  (`module: esnext`, `verbatimModuleSyntax: true`), then
  `node scripts/rename-to-esm-files.js dist/esm`, which rewrites relative
  import specifiers and renames `.js` → `.mjs` and `.d.ts` → `.d.mts`

Both extend `tsconfig.base.json`: `strict`, `target: ES6`,
`moduleResolution: node`, `declaration`, `isolatedModules`,
`isolatedDeclarations`. `tsconfig.json` simply extends the CJS config so
editors and bare `tsc` see that variant.

`package.json` `exports` maps the root plus `./serialization` and one subpath per
resource (`./experience`, `./template`, `./component`, `./fragment`,
`./experienceFragment`, `./release`, `./release/experience`,
`./release/fragment`), each with separate `import`/`require` conditions. Combined
with `sideEffects: false`, that lets bundlers pull in a single resource client
instead of the whole SDK. The `browser` field stubs out `fs`, `os`, `path`,
`stream` and `crypto` to `false`.

`dist/` is gitignored. There is no `prepare` or `postinstall` script, so a git
URL install yields a non-functional package — see [BUILDING.md](./BUILDING.md).

## Tests

`vitest.config.mts` defines one project, `unit`, rooted at `./tests` with
`tests/setup.ts` (which registers a `toContainHeaders` custom matcher) and
`typecheck.enabled: true` against `tests/tsconfig.json`. `passWithNoTests` is on.

Coverage is of the core runtime — `tests/unit/fetcher/`, `tests/unit/schemas/`,
`tests/unit/url/`, `tests/unit/auth/`, `tests/unit/logging/`. No test calls the
live API, so no Contentful credentials are required. `tests/custom.test.ts` is
the generator's placeholder for hand-written tests.

## Release and versioning

`package.json` stays at a Fern placeholder version. `.github/workflows/publish.yml`
fires on any `v*` tag push, pulls a GitHub Packages write token from Vault
(role `<repo-name>-github-action`), sets the version from the tag ephemerally
with `npm version --no-git-tag-version`, builds, and publishes to GitHub
Packages — inferring the dist-tag from the pre-release identifier (`beta`,
`alpha`, `rc`, `dev`) or `latest`. Org infrastructure mirrors to npmjs from
there. Full procedure and troubleshooting table: [RELEASING.md](./RELEASING.md).

CI on every push (`.github/workflows/ci.yml`) is two jobs: `compile`
(`pnpm build`) and `test` (`pnpm test`).

## Legal artifacts

`NOTICE` and `licenses/` are generated from direct dependencies by
`scripts/update-licenses.js` (`pnpm run update-licenses`), which handles
composite SPDX expressions such as `MIT OR Apache-2.0`. Because dependency
changes here normally arrive via SDK regeneration, that script should be re-run
after a regeneration. See [AUTOMATION-FOR-LICENSES.md](./AUTOMATION-FOR-LICENSES.md).

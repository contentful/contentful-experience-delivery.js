# AGENTS.md

Operating instructions for coding agents working in
`contentful-experience-delivery.js`. Human contributors should start with
[CONTRIBUTING.md](./CONTRIBUTING.md); this file covers the constraints that are
easy for an agent to violate.

## What this repo is

`@contentful/experience-delivery` is a TypeScript client for Contentful's
Experience Delivery and Preview API (`https://xdn.contentful.com`). **The vast
majority of it is generated by [Fern](https://buildwithfern.com) from an API
definition that lives in a different repository** — see
[ARCHITECTURE.md](./ARCHITECTURE.md) for the layering and the generation
pipeline.

## Rule 1: do not edit generated files

`src/` contains 782 TypeScript files. Almost all of them start with:

```
// This file was auto-generated by Fern from our API Definition.
```

Edits to those files are silently discarded on the next SDK regeneration. If a
change belongs in the API surface (a new endpoint, a changed type, a fixed
description), it has to happen in the upstream API definition — not here.

### The files you may edit

`.fernignore` is the authoritative list of hand-maintained paths. As of this
writing it covers:

`.contentful/vault-secrets.yaml`, `.fern/replay.lock`, `.fern/replay.yml`,
`.gitattributes`, `RELEASING.md`, `.github/workflows/publish.yml`,
`CONTRIBUTING.md`, `LICENSE`, `NOTICE`, `licenses/`,
`AUTOMATION-FOR-LICENSES.md`, `scripts/update-licenses.js`,
`catalog-info.yaml`, `.github/CODEOWNERS`, `.github/ISSUE_TEMPLATE/`,
`.github/pull_request_template.md`, `BUILDING.md`, `AGENTS.md`,
`ARCHITECTURE.md`, `docs/`

**Read `.fernignore` rather than trusting that list** — it changes. If you add a
new hand-maintained file, add it to `.fernignore` in the same change, or it will
be deleted or overwritten by the generator.

There is a second, weaker safety net: Fern Replay records hand-made commits in
`.fern/replay.lock` and reapplies them on top of new generations. It is not a
substitute for `.fernignore` and it does not always converge — see
[docs/ADRs/2026-08-25-preserve-hand-maintained-files-across-fern-regeneration.md](./docs/ADRs/2026-08-25-preserve-hand-maintained-files-across-fern-regeneration.md).

## Environment

- **Node.js 22 or higher** (`engines.node` is `>=22.0.0`).
- **pnpm 10.33.0**, pinned via `packageManager`. Enable it with
  `corepack enable`. Do not substitute npm or yarn; `pnpm-lock.yaml` is the
  committed lockfile and CI installs with `--frozen-lockfile`.

## Commands

Every command below is defined in `package.json`.

| Task | Command |
| --- | --- |
| Install | `pnpm install` |
| Build both targets | `pnpm build` |
| Build CommonJS only | `pnpm build:cjs` |
| Build ESM only | `pnpm build:esm` |
| Run all tests | `pnpm test` |
| Run the unit project | `pnpm test:unit` |
| Lint | `pnpm lint` |
| Lint and autofix | `pnpm lint:fix` |
| Check formatting | `pnpm format:check` |
| Rewrite formatting | `pnpm format` |
| Lint + format together | `pnpm check` / `pnpm check:fix` |
| Refresh `NOTICE` and `licenses/` | `pnpm run update-licenses` |

Note: `CONTRIBUTING.md` mentions `pnpm run format:fix`. That script does not
exist in `package.json` — use `pnpm format` (which writes) or `pnpm check:fix`.

Linting and formatting are both [Biome](https://biomejs.dev) 2.4.10, configured
in `biome.json`: 4-space indent, 120-column lines, double quotes. Match that;
the generator emits code in exactly that style.

## Testing

- Tests live in `tests/`. `vitest.config.mts` defines a single project named
  `unit`, rooted at `./tests`, with `tests/setup.ts` as a setup file and
  `typecheck.enabled: true` (so type errors in tests fail the run).
- Coverage is of the **core runtime layer** — `tests/unit/fetcher/`,
  `tests/unit/schemas/`, `tests/unit/url/`, `tests/unit/auth/`,
  `tests/unit/logging/`. There are no endpoint or wire tests; the generator
  config in `.fern/metadata.json` sets `generateWireTests: false`.
- **No Contentful credentials are needed.** Nothing in `tests/` calls the live
  API. If you find yourself needing a real token to make a test pass, you are
  writing the wrong kind of test for this repo.
- `tests/custom.test.ts` is the placeholder the generator provides for
  hand-written tests. Its own comment says to add it to `.fernignore`; it is
  currently **not** listed there, so treat anything you put in it as
  unprotected until that entry is added.

## Things not to do

- **Do not commit `dist/`.** It is gitignored and produced by `pnpm build`.
- **Do not hand-edit the version.** `package.json` stays at a Fern placeholder
  (`0.0.0-fern-placeholder.6`); the publish workflow derives the real version
  from the git tag at release time. `src/version.ts` and the `X-Fern-SDK-Version`
  header in `src/BaseClient.ts` are generated from the same placeholder.
- **Do not push a `v*` tag.** Any tag matching `v*` triggers
  `.github/workflows/publish.yml` and publishes to GitHub Packages. See
  [RELEASING.md](./RELEASING.md).
- **Do not weaken `.gitignore`** or add anything under `.contentful/` —
  `.contentful/vault-secrets.yaml` governs the Vault role used by the publish
  workflow.
- **Do not edit `.fern/replay.lock`.** It is machine-managed and marked
  `linguist-generated` in `.gitattributes`.

## CI and conventions

- `.github/workflows/ci.yml` runs on every push: a `compile` job (`pnpm build`)
  and a `test` job (`pnpm test`), both after `pnpm install --frozen-lockfile`.
- `.fern/verify.sh` is the generator's own gate and runs `pnpm install`,
  `pnpm build`, `pnpm test` in sequence — a useful local proxy for CI.
- Commits follow [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/)
  with the Jira key in brackets, e.g.
  `chore: add CODEOWNERS file [DX-1197] (#10)`. Generated commits are authored
  by `fern-api[bot]` and titled `SDK regeneration`.
- CODEOWNERS is `@contentful/group-ecosystem`; `catalog-info.yaml` records
  `group:team-developer-experience` as the Backstage owner at service tier 4.

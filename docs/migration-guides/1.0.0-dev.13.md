# @contentful/experience-delivery — Changelog & Migration Guide

---

## 1. Space/environment binding

changed every experience/fragment/destination method from

```ts
client.experience.get(spaceId, environmentId, id, opts)
```

to

```ts
client.experience.get(id, opts) // spaceId/environmentId now bound at client construction
```

---

## 2. Personalization data — new fields, and 5 event types reshaped

API replaced XDA's hand-written, strict personalization schemas with the shared `@contentful/optimization-api-client` ones. That change is now reflected in the SDK's `Personalization*Event` family: `PersonalizationPageEvent`, `PersonalizationTrackEvent`, `PersonalizationIdentifyEvent`, `PersonalizationScreenEvent`, `PersonalizationComponentEvent`.

### 2a. Breaking: new required fields

| Field | Before | After |
|---|---|---|
| `context.campaign` | optional | **required** |
| `originalTimestamp` | optional | **required** |
| `sentAt` | optional | **required** |
| `properties.title` (page/track events) | optional | **required** |

**Migration:** any hand-built event payload (i.e. not produced by the Experiences SDK's own `EventBuilder`) must now supply `campaign`, `originalTimestamp`, `sentAt`, and — for page/track events — `properties.title`. This is the exact failure this PR's `usage.ts` fix addresses (`TS2322: Property 'campaign' is missing`).

```diff
  const event: PersonalizationPageEvent = {
    channel: "web",
    context: {
      library: { name: "my-app", version: "1.0.0" },
+     campaign: {}, // now required — pass {} if you have no campaign data
    },
    messageId: "...",
+   originalTimestamp: new Date().toISOString(),
+   sentAt: new Date().toISOString(),
    timestamp: new Date().toISOString(),
    properties: {
+     title: "Home page",
    },
  };
```

### 2b. Breaking: `Channel` loses its runtime enum object

```diff
- export const Channel = {
-     Web: "web", Mobile: "mobile", Server: "server", Client: "client",
- } as const;
- export type Channel = (typeof Channel)[keyof typeof Channel];
+ export type Channel = ("mobile" | "server" | "web") | "client";
```

**Migration:** code written as `Channel.Web` no longer compiles or runs — `Channel` is now a type only, with no runtime object. Replace with the literal string:

```diff
- channel: PersonalizationPageEvent.Channel.Web,
+ channel: "web",
```

### 2c. New, non-breaking additions

- **`screen` context** added to `Track`/`Identify`/`Screen`/`Component` events (`context.screen: { name: string }`).
- **`anonymousId?: string`** added to all five event types.
- **`preflight?: boolean`** added to `client.experience.getWithOverrides(id, { extensions: { personalization: { preflight } } })` — lets a caller request a dry-run/validation pass without committing the personalized read. (Per this PR's own evidence report, the upstream *response* side of preflight isn't present yet — only the request field.)

### 2d. Previously "loose" fields are now strictly typed

`properties`, `page`, and `traits` on these event types used to allow arbitrary extra keys via `[key: string]: any`. They're now typed as `Record<string, <AutoNamedSchema>>` — see §4 below for what that type actually is. Functionally this is more correct (it documents that extra keys are arbitrary JSON, not literally `any`), but if your code relied on `as any` casts through these fields, you may now get a slightly different inferred type at the call site.

## 3. HydratedView / HydratedExperienceView / HydratedFragmentView — new personalization profile data

These three view-response types gain two previously-absent capabilities inside `extensions.personalization.profile`:

- **`session.landingPage`** can now carry arbitrary extra properties beyond its known fields (`path`, `query`, `referrer`, `search`, `url`) — previously this object was closed (`additionalProperties: false`).
- **`changes[]`** entries of kind `"Variable"` gain a new `value` field (previously `Variable` changes had no `value` at all, just `{ type: "Variable" }`).

Both are additive — nothing here breaks existing code, but if you're pattern-matching on `changes[]` shapes, a `"Variable"` entry can now carry a `value`.

## 4. The 14 new auto-named types — do not depend on these

14 schemas (10 in Delivery, 4 in Destinations) are **unsafe** to use, and expected to be removed without further notice in a future release.

```ts
export type GetSpacesSpaceIdEnvironmentsEnvironmentIdExperiencesId0200Schema1 =
    | string | number | boolean
    | (ContentfulViewDelivery.GetSpacesSpaceIdEnvironmentsEnvironmentIdExperiencesId0200Schema1 | undefined)[]
    | { [key: string]: GetSpacesSpaceIdEnvironmentsEnvironmentIdExperiencesId0200Schema1 };
```

All 14 are the exact same shape — a recursive "any JSON value" union — duplicated once per call site instead of collapsed into one shared type:

- `GetSpacesSpaceIdEnvironmentsEnvironmentIdExperiencesId0200Schema1/2/3`
- `GetSpacesSpaceIdEnvironmentsEnvironmentIdTimelineFragmentsId3200Schema1/2/3`
- `PostSpacesSpaceIdEnvironmentsEnvironmentIdExperiencesId1BodySchema0/1/2/3`
- `PostSpacesSpaceIdDestinationsDestinationIdNodesNodeIdExperiences3BodySchema0/1/2/3`

They show up wherever a personalization field is typed as arbitrary JSON — `profile.traits`, `session.landingPage`'s extra keys, `changes[].value`, and the event `page`/`screen`/`properties`/`traits` fields covered in §2.

> **⚠️ Treat these as unstable.** they are not a deliberate, versioned part of the public API. A future release is likely to collapse them into a single shared type (something like `JsonValue`), rename them, renumber them, or otherwise change them **without a deprecation cycle**.
>
> **Recommended usage:** don't import these types directly. Where you need the *shape* (any JSON value), declare your own local type instead of depending on the generated one:
> ```ts
> type JsonValue = string | number | boolean | null | JsonValue[] | { [key: string]: JsonValue };
> ```

## Summary

| Category | Breaking? | Needs action? |
|---|---|---|
| Space/env client-variable binding | Yes | Pass space/environment id on client initialization, remove from method params |
| `campaign`/`originalTimestamp`/`sentAt`/`title` now required | **Yes** | Update any hand-built event payloads |
| `Channel` enum → string union | **Yes** | Replace `Channel.Web` etc. with string literals |
| `screen`, `anonymousId`, `preflight` added | No | Optional, no action |
| `landingPage`/`changes[].value` additive fields | No | Optional, no action |
| 14 auto-named `*SchemaN` types | No (today) | Don't depend on these names; expect churn without notice |
